  <action>
1. Install dependencies in server workspace:
   ```
   yarn workspace server add redis @socket.io/redis-adapter p-queue
   ```
   Note: p-queue is ESM-only. The server already uses ESM (type: "module" in server/package.json), so this is fine.

2. Create `server/src/services/redis.ts`:
   - Import `createClient` from `redis` (node-redis, NOT ioredis per research).
   - Import `config` from `./config.js`.
   - Create singleton: `export const redisClient = createClient({ url: config.REDIS_URL || "redis://localhost:6379" })`.
   - Add error listener: `redisClient.on("error", (err) => console.error("[redis] client error:", err))`.
   - Export `async function connectRedis(): Promise<void>` — calls `await redisClient.connect()` only if `!redisClient.isOpen`. Logs `[redis] connected` on success. IMPORTANT: node-redis requires explicit .connect() — it does NOT auto-connect.
   - Export `function isRedisAvailable(): boolean` — returns `redisClient.isOpen`. Used by other modules to gracefully degrade when Redis is unavailable.
   - If `config.REDIS_URL` is blank, `connectRedis()` should skip connection and log a warning: `[redis] REDIS_URL not configured — running without Redis (in-memory fallback)`. Set a module-level flag `let redisEnabled = false` that `isRedisAvailable()` checks.

3. Create `server/src/services/bedrockQueue.ts`:
   - Import `PQueue` from `p-queue` (default export, ESM package).
   - Create: `export const bedrockQueue = new PQueue({ concurrency: 20 })`. Start with 20 concurrent (conservative, per research open question #3 — tune upward based on Datadog monitoring).
   - Export `async function queueBedrockCall<T>(fn: () => Promise<T>): Promise<T>` — wraps `fn` in `bedrockQueue.add(fn)`, returns result.
   - Export `function isBedrockQueueOverloaded(): boolean` — returns `bedrockQueue.pending > 100`. Used by routes to return 503 before queuing when backpressure is extreme.

4. Update `server/src/services/config.ts`:
   - Add to `envDefaults`: `REDIS_URL: ""`, `JWT_SECRET: ""`, `SESSION_SECRET: ""`.
   - Add to `envSchema`: `REDIS_URL: z.string()`, `JWT_SECRET: z.string()`, `SESSION_SECRET: z.string()`.
   - Follow the existing blank-default pattern (empty string = feature disabled gracefully).

5. Update `.env.example`:
   - Add a `# Redis` section after S3:
     ```
     # Redis (conversation persistence, rate limiting, sessions)
     REDIS_URL=redis://localhost:6379
     ```
   - Add a `# Auth` section:
     ```
     # Auth (JWT)
     JWT_SECRET=                  # generate: node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
     SESSION_SECRET=              # generate: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
     ```

2. Update `server/src/sockets/index.ts`:
   - Import `{ createAdapter } from "@socket.io/redis-adapter"`.
   - Import `{ redisClient, isRedisAvailable } from "../services/redis.js"`.
   - After `io = new Server(...)` creation but BEFORE `io.on("connection", ...)`:
     - Check `if (isRedisAvailable())` — only wire Redis adapter when Redis is connected.
     - Create subscriber client: `const subClient = redisClient.duplicate()`.
     - Connect subscriber: `await subClient.connect()`.
     - Attach adapter: `io.adapter(createAdapter(redisClient, subClient))`.
     - Log: `console.log("[socket.io] Redis adapter attached")`.
   - Because the adapter setup is async (subClient.connect()), change `initSocketIO` to return `Promise<Server<...>>`. Update the call in index.ts to `await initSocketIO(server)`.
   - CRITICAL: The standard Redis adapter does NOT support connectionStateRecovery across instances (per research). Keep the existing `connectionStateRecovery` config as-is — it still works for single-instance. Add a comment noting the limitation.
