<objective>
Replace aggressive fixed-interval polling in music and video client services with exponential backoff and initial delays, and add server-side `startedAt` timestamps on 202 responses.

Purpose: Reduce wasted 202 polling requests by ~60-75% (music ~14 to ~5-6 polls, video ~36 to ~9 polls), lowering server load and console noise for 1000 concurrent users.

Output: Six modified files -- server cache entries gain `generationStartedAt`, server routes include `startedAt` in 202 JSON, client services replace fixed poll intervals with exponential backoff + initial delay.
</objective>

**backgroundMusic.ts:**

1. Replace the `POLL_INTERVAL_MS = 4000` constant with three new constants:
   ```typescript
   const INITIAL_POLL_DELAY_MS = 10_000;
   const BACKOFF_BASE_MS = 2_000;
   const BACKOFF_CAP_MS = 30_000;
   ```
   Remove the `POLL_INTERVAL_MS` line entirely.

2. Add a module-level helper function (above `fetchMoodAudio`):
   ```typescript
   function getPollDelay(pollCount: number): number {
     return Math.min(BACKOFF_BASE_MS * Math.pow(2, pollCount), BACKOFF_CAP_MS);
   }
   ```

3. In `fetchMoodAudio`, replace the 202-handling block's `setTimeout` delay. The current code (lines ~95-100) uses `POLL_INTERVAL_MS`. Replace with:
   ```typescript
   if (res.status === 202) {
     pollCounts.set(mood, polls + 1);
     if (polls + 1 > MAX_POLLS) {
       console.warn(`[music] max polls for ${mood} — giving up`);
       fetchingMoods.delete(mood);
       return null;
     }

     // Initial delay on first 202 (skip the guaranteed-not-ready window),
     // then exponential backoff on subsequent polls
     const delay = polls === 0 ? INITIAL_POLL_DELAY_MS : getPollDelay(polls);

     return new Promise((resolve) => {
       setTimeout(async () => {
         fetchingMoods.delete(mood);
         resolve(await fetchMoodAudio(mood));
       }, delay);
     });
   }
   ```

   CRITICAL: The initial delay fires INSIDE the 202 handler, not before the first fetch. This means if the server already has cached audio (200 response), there is zero delay. The 10s delay only applies when the server returns 202 for the first time for a given mood.

4. Do NOT change the error retry path -- `RETRY_INTERVAL_MS` remains `10000` and is used only for non-2xx error retries.

5. Verify `stopBackgroundMusic()` still calls `pollCounts.clear()` and `retryCounts.clear()` -- these ensure poll counts reset on stop. No changes needed to this function.

6. Verify `fetchingMoods` guard is preserved exactly: `fetchingMoods.add(mood)` at top of function, `fetchingMoods.delete(mood)` before each recursive call and on each exit path.
