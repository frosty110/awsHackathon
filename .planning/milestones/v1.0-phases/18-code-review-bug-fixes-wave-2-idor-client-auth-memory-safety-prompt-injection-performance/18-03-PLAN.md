<objective>
Replace unbounded in-memory Map caches with byte-budget LRU caches using the `lru-cache` npm package (criterion 4).

Purpose: The TTS, video, and music caches currently use plain Maps with count-based eviction only. At 1000 concurrent users, each TTS entry can be 10-40MB, each video 20-100MB. Without byte limits, the server will OOM. LRU with byte budgets caps total memory consumption.

Output: Three caches converted to LRUCache with maxSize (bytes), sizeCalculation, and TTL.
</objective>

       - Replace with LRUCache. The challenge is that entries contain metadata (generating, error, retryCount) in addition to the video Buffer.
       - Approach: Keep the metadata Map for generation state, but use LRUCache for the actual video Buffers.
         ```typescript
         const videoBufferCache = new LRUCache<string, Buffer>({
           maxSize: 500 * 1024 * 1024, // 500MB byte budget
           sizeCalculation: (buf) => buf.byteLength,
           ttl: 60 * 60 * 1000, // 1 hour TTL
           allowStale: false,
         });
         ```
       - Keep `sceneVideoCache` Map for metadata (generating state, error, retry info), but when storing/retrieving the video Buffer, use `videoBufferCache` instead of `entry.video`.
       - Update any code that reads `entry.video` to read from `videoBufferCache.get(scene)`.
       - Update any code that writes `entry.video = buffer` to `videoBufferCache.set(scene, buffer)` and `entry.video = true` (or similar flag).
       - Actually, simpler approach: replace the entire sceneVideoCache with a structure that separates concerns cleanly. The metadata (generating/error/retry) stays in a plain Map. The Buffer goes in LRUCache.
       - Update `getSceneVideoStats()` to report `videoBufferCache.calculatedSize` for byte usage.

           ttl: 60 * 60 * 1000, // 1 hour TTL

         });

       - Keep `moodCache` Map for metadata. Store/retrieve audio Buffers from `musicBufferCache`.
       - Update `getMusicCacheStats()` to include byte usage from `musicBufferCache.calculatedSize`.

    NOTE: The key insight is that video and music caches have dual concerns (generation state tracking + buffer storage). Separating them avoids fighting the LRUCache API while still getting byte-budget eviction for the memory-heavy Buffers.
