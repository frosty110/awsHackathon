  <action>
    1. Create `server/src/services/config.ts`:
       - Import `z` from `"zod"`
       - Define `envSchema = z.object({...})` with these fields:
         - `NODE_ENV`: `z.enum(["development", "production", "test"]).default("development")`
         - `PORT`: `z.coerce.number().default(3001)`
         - `AWS_REGION`: `z.string().min(1)` (required)
         - `AWS_ACCESS_KEY_ID`: `z.string().optional()` (optional — supports SSO/credential chain per research)
         - `AWS_SECRET_ACCESS_KEY`: `z.string().optional()` (optional — same reason)
         - `BEDROCK_MODEL_ID`: `z.string().min(1)` (required — resolves open question from research about inference profile IDs vs model IDs)
         - `NEO4J_URI`: `z.string().min(1)` (use min(1) not url() — Neo4j URIs use neo4j+s:// scheme which may not pass URL validation)
         - `NEO4J_USERNAME`: `z.string().min(1)`
         - `NEO4J_PASSWORD`: `z.string().min(1)`
         - `DATADOG_API_KEY`: `z.string().min(1)`
         - `MINIMAX_API_KEY`: `z.string().min(1)`
         - `MINIMAX_GROUP_ID`: `z.string().min(1)`
       - Use `safeParse(process.env)`:
         - On failure: `console.error("Environment validation failed:")`, then `console.error(result.error.format())`, then `process.exit(1)`
         - On success: `export const config = result.data`
       - `export type Config = typeof config`
       - NOTE: Use Zod v4 syntax — `error` not `message` for custom error params (though we don't need custom messages for basic validation)

    2. Create `.env.example` documenting all required keys with comments:
       ```
       # AWS (required — use @aws-sdk/client-bedrock-runtime ONLY, not @anthropic-ai/bedrock-sdk)
       AWS_REGION=us-east-1
       AWS_ACCESS_KEY_ID=           # optional if using instance role / AWS SSO
       AWS_SECRET_ACCESS_KEY=       # optional if using instance role / AWS SSO
       BEDROCK_MODEL_ID=            # e.g. anthropic.claude-3-sonnet-20240229-v1:0 — verify in your region

       # Neo4j
       NEO4J_URI=neo4j+s://your-instance.databases.neo4j.io
       NEO4J_USERNAME=neo4j
       NEO4J_PASSWORD=

       # Datadog
       DATADOG_API_KEY=

       # MiniMax TTS (opening monologue only)
       MINIMAX_API_KEY=
       MINIMAX_GROUP_ID=            # found in MiniMax platform dashboard

       # Server
       PORT=3001
       NODE_ENV=development
       ```

    3. Create `.env` as a copy of `.env.example` with placeholder values filled in for LOCAL DEV ONLY (so `npm run dev` does not crash on missing env vars during scaffold testing). Use dummy values like `dummy-key`, `bolt://localhost:7687`, etc. This file is gitignored.
       - For NEO4J_URI use `bolt://localhost:7687` (won't connect but allows server to attempt boot)
       - All other keys: use `placeholder` or `dummy` values
       - Set AWS_REGION to `us-east-1`

<task type="auto">
  <name>Task 2: Create health route, server entry point, wire into app, and verify full boot</name>
  <files>
    server/src/routes/health.ts

  <action>
    1. Create `server/src/routes/health.ts`:
       ```typescript
       import { Router } from "express";

       const router = Router();

       router.get("/health", (_req, res) => {
         res.status(200).json({
           status: "ok",
           timestamp: new Date().toISOString(),
           uptime: process.uptime(),
         });
       });

       export default router;
       ```

    2. Update `server/src/app.ts` (created in Plan 01) to import and mount the health router:
       - Add: `import healthRouter from "./routes/health.js";` (NOTE: .js extension required for NodeNext)
       - Add: `app.use(healthRouter);` inside createApp before the return
       - Keep the existing express.json() middleware and AppDeps interface

    3. Create `server/src/index.ts` — the server entry point:
       - FIRST LINE must be: `import "dotenv/config";` (loads .env before any other imports — critical for config.ts to see env vars)
       - Second import: `import { config } from "./services/config.js";` (.js extension for NodeNext)
       - Then import neo4j, createApp, createServer
       - In `async function main()`:
         a. Create Neo4j driver: `neo4j.driver(config.NEO4J_URI, neo4j.auth.basic(config.NEO4J_USERNAME, config.NEO4J_PASSWORD))`
         b. Try `await driver.verifyConnectivity()` — log success on resolve, catch errors and `process.exit(1)` on failure (verifyConnectivity returns void in v6, do NOT use return value)
         c. Call `createApp({ driver })` to get the Express app
         d. `createServer(app).listen(config.PORT, () => console.log(...))`
       - Wrap `main()` in `.catch()` for fatal startup errors
       - IMPORTANT: The Neo4j verifyConnectivity will FAIL with placeholder .env values. This is expected and correct behavior — the scaffold is wired correctly, it just needs real credentials. Add a TODO comment noting this.
       - For dev testing WITHOUT Neo4j: wrap the verifyConnectivity block so it logs a warning but does NOT exit if NODE_ENV is "development". This way `npm run dev` works during scaffold testing.

    4. Verify the full boot:
       - Run `npm run dev` from project root (will start both client and server via concurrently)
       - Server should start on port 3001 (may warn about Neo4j connection with placeholder values)
       - Client should start on port 5173
       - `curl http://localhost:3001/health` should return `{"status":"ok","timestamp":"...","uptime":...}`
       - Kill the dev servers after verification
  </action>
