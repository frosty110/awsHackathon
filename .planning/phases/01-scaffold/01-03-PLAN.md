  <files>server/src/services/config.ts</files>
  <action>
    Rewrite `server/src/services/config.ts` to implement the blank-default + warning-first pattern from the original 01-02-PLAN.md specification. The current file hard-fails on 9 integration keys via `.min(1)` — this must change to soft defaults with deferred validation.

    Specific changes:

    1. **Add `envDefaults` object** as the single source of blank defaults for all integration keys:
       ```typescript
       const envDefaults: Record<string, string> = {
         NODE_ENV: "development",
         PORT: "3001",
         AWS_REGION: "",
         AWS_ACCESS_KEY_ID: "",
         AWS_SECRET_ACCESS_KEY: "",
         BEDROCK_MODEL_ID: "",
         NEO4J_URI: "",
         NEO4J_USERNAME: "",
         NEO4J_PASSWORD: "",
         DD_API_KEY: "",
         DD_SITE: "datadoghq.com",
         DD_LLMOBS_ENABLED: "1",
         DD_LLMOBS_ML_APP: "",
         DD_LLMOBS_AGENTLESS_ENABLED: "1",
         DD_TRACE_AWS_SDK_BEDROCKRUNTIME_ENABLED: "true",
         MINIMAX_API_KEY: "",
         MINIMAX_GROUP_ID: "",
         SKIP_NEO4J_CONNECTIVITY_CHECK: "0",
       };
       ```

    2. **Remove all `.min(1)` from the Zod schema.** Every string key becomes plain `z.string()` with no minimum length. Remove the regex from `NEO4J_URI` (it will be validated at usage time via `requireConfigValues`). Keep `z.enum()` validators for the fixed-set keys (NODE_ENV, DD_LLMOBS_ENABLED, DD_LLMOBS_AGENTLESS_ENABLED, DD_TRACE_AWS_SDK_BEDROCKRUNTIME_ENABLED, SKIP_NEO4J_CONNECTIVITY_CHECK). Keep `z.coerce.number()` for PORT. Remove `.optional()` from AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY (envDefaults provides the blank default). Remove `.default()` from all fields (envDefaults handles defaults via the merge).

    3. **Change parse input** from `envSchema.safeParse(process.env)` to `envSchema.safeParse({ ...envDefaults, ...process.env })` so unset keys resolve to their defaults.

    4. **Keep the hard-fail on parse errors** — `process.exit(1)` stays for actual type/schema violations (e.g., PORT set to "abc"). These are real configuration errors, not missing optional keys.

    5. **Export `warnOnBlankConfig` helper:**
       ```typescript
       export function warnOnBlankConfig(keys: Array<keyof Config>, context: string): void {
         const blank = keys.filter((k) => config[k] === "" || config[k] === undefined);
         if (blank.length > 0) {
           console.warn(`[config] ${context}: missing values for ${blank.join(", ")} — features using these keys will fail at runtime`);
         }
       }
       ```

    6. **Export `requireConfigValues` helper:**
       ```typescript
       export function requireConfigValues(keys: Array<keyof Config>, context: string): void {
         const blank = keys.filter((k) => config[k] === "" || config[k] === undefined);
         if (blank.length > 0) {
           throw new Error(`[config] ${context}: required values missing for ${blank.join(", ")}`);
         }
       }
       ```

    7. **Continue exporting** `config` and `Config` type as before.

  <name>Task 2: Update index.ts with startup warnings and conditional Neo4j driver creation</name>
  <files>server/src/index.ts</files>
  <action>
    Update `server/src/index.ts` to use the new warn/require helpers from config.ts and restructure Neo4j initialization so the driver is never instantiated with blank values.

    **CRITICAL ordering:** `neo4j.driver("")` throws `Error: Illegal host` synchronously. After Task 1 softens the schema, NEO4J_URI defaults to `""`. The driver must NOT be created when Neo4j keys are blank and skip is allowed. Compute `allowNeo4jSkip` FIRST, then gate all Neo4j work behind it.

    Specific changes:

    1. **Update the config import** from:
       ```typescript
       import { config } from "./services/config.js";
       ```
       to:
       ```typescript
       import { config, warnOnBlankConfig, requireConfigValues } from "./services/config.js";
       ```

    2. **Add startup warnings** at the beginning of `main()`, BEFORE any Neo4j logic:
       ```typescript
       warnOnBlankConfig(
         ["AWS_REGION", "BEDROCK_MODEL_ID"],
         "AWS Bedrock (needed in Phase 4)"
       );
       warnOnBlankConfig(
         ["DD_API_KEY", "DD_LLMOBS_ML_APP"],
         "Datadog LLM Observability (needed in Phase 6)"
       );
       warnOnBlankConfig(
         ["MINIMAX_API_KEY", "MINIMAX_GROUP_ID"],
         "MiniMax TTS (needed in Phase 7)"
       );
       ```

    3. **Compute `allowNeo4jSkip` FIRST** (before any driver creation):
       ```typescript
       const allowNeo4jSkip =
         config.SKIP_NEO4J_CONNECTIVITY_CHECK === "1" && config.NODE_ENV !== "production";
       ```

    4. **Move entire Neo4j block (driver creation + verifyConnectivity) inside a conditional.** Replace the current unconditional `neo4j.driver()` call and try/catch with:
       ```typescript
       let driver: neo4j.Driver | null = null;

       if (allowNeo4jSkip) {
         warnOnBlankConfig(
           ["NEO4J_URI", "NEO4J_USERNAME", "NEO4J_PASSWORD"],
           "Neo4j (skipping connectivity check)"
         );
       } else {
         requireConfigValues(
           ["NEO4J_URI", "NEO4J_USERNAME", "NEO4J_PASSWORD"],
           "Neo4j connectivity check"
         );
         driver = neo4j.driver(
           config.NEO4J_URI,
           neo4j.auth.basic(config.NEO4J_USERNAME, config.NEO4J_PASSWORD)
         );
         try {
           await driver.verifyConnectivity();
           console.log("Neo4j connectivity verified");
         } catch (error) {
           console.error("Neo4j connectivity check failed:", error);
           await driver.close();
           process.exit(1);
         }
       }
       ```
       This ensures `neo4j.driver()` is NEVER called with blank/empty strings. When skip is on, `driver` stays `null` and a warning is emitted instead.

    5. **Pass `driver` (possibly null) to `createApp`**. The existing `createApp({ driver })` call stays the same — it already receives the driver variable. Downstream code must handle `driver: null` (this is expected; Neo4j failures degrade gracefully per CLAUDE.md reliability requirements).

    6. **Keep everything else unchanged**: the dotenv/config first-line import, createApp call, server.listen call, and main().catch() wrapper all stay as-is.
