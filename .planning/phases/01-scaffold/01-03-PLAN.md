  <action>
    Rewrite `server/src/services/config.ts` to implement the blank-default + warning-first pattern from the original 01-02-PLAN.md specification. The current file hard-fails on 9 integration keys via `.min(1)` — this must change to soft defaults with deferred validation.

    Specific changes:

    1. **Add `envDefaults` object** as the single source of blank defaults for all integration keys:
       ```typescript
       const envDefaults: Record<string, string> = {
         NODE_ENV: "development",
         PORT: "3001",
         AWS_REGION: "",
         AWS_ACCESS_KEY_ID: "",
         AWS_SECRET_ACCESS_KEY: "",
         BEDROCK_MODEL_ID: "",
         NEO4J_URI: "",
         NEO4J_USERNAME: "",
         NEO4J_PASSWORD: "",
         DD_API_KEY: "",
         DD_SITE: "datadoghq.com",
         DD_LLMOBS_ENABLED: "1",
         DD_LLMOBS_ML_APP: "",
         DD_LLMOBS_AGENTLESS_ENABLED: "1",
         DD_TRACE_AWS_SDK_BEDROCKRUNTIME_ENABLED: "true",
         MINIMAX_API_KEY: "",
         MINIMAX_GROUP_ID: "",
         SKIP_NEO4J_CONNECTIVITY_CHECK: "0",
       };
       ```

    2. **Remove all `.min(1)` from the Zod schema.** Every string key becomes plain `z.string()` with no minimum length. Remove the regex from `NEO4J_URI` (it will be validated at usage time via `requireConfigValues`). Keep `z.enum()` validators for the fixed-set keys (NODE_ENV, DD_LLMOBS_ENABLED, DD_LLMOBS_AGENTLESS_ENABLED, DD_TRACE_AWS_SDK_BEDROCKRUNTIME_ENABLED, SKIP_NEO4J_CONNECTIVITY_CHECK). Keep `z.coerce.number()` for PORT. Remove `.optional()` from AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY (envDefaults provides the blank default). Remove `.default()` from all fields (envDefaults handles defaults via the merge).

    3. **Change parse input** from `envSchema.safeParse(process.env)` to `envSchema.safeParse({ ...envDefaults, ...process.env })` so unset keys resolve to their defaults.

    4. **Keep the hard-fail on parse errors** — `process.exit(1)` stays for actual type/schema violations (e.g., PORT set to "abc"). These are real configuration errors, not missing optional keys.

    5. **Export `warnOnBlankConfig` helper:**
       ```typescript
       export function warnOnBlankConfig(keys: Array<keyof Config>, context: string): void {
         const blank = keys.filter((k) => config[k] === "" || config[k] === undefined);
         if (blank.length > 0) {
           console.warn(`[config] ${context}: missing values for ${blank.join(", ")} — features using these keys will fail at runtime`);
         }
       }
       ```

    6. **Export `requireConfigValues` helper:**
       ```typescript
       export function requireConfigValues(keys: Array<keyof Config>, context: string): void {
         const blank = keys.filter((k) => config[k] === "" || config[k] === undefined);
         if (blank.length > 0) {
           throw new Error(`[config] ${context}: required values missing for ${blank.join(", ")}`);
         }
       }
       ```

    7. **Continue exporting** `config` and `Config` type as before.
  </action>
