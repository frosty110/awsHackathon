**saveStore.ts** — Create a Redis-backed save store service following the patterns in conversationStore.ts:

Types:
```typescript
export interface SaveMeta {
  name: string;
  characterClass: string;
  pronouns: string;
  turnCount: number;
  savedAt: number;      // Unix ms
  lastPlayedAt: number; // Unix ms
  mode: 'single' | 'multi';
}

export interface SaveRecord extends SaveMeta {
  conversationId: string;
}
```

Constants:
- `MAX_SAVES = 10`
- `SAVE_HASH_TTL_SECONDS = 90 * 24 * 60 * 60` (90 days)

Redis key functions (follow `redisKey()` pattern from conversationStore.ts):
- `savesIndexKey(userId: string)` returns `saves:${userId}`
- `saveHashKey(userId: string, conversationId: string)` returns `save:${userId}:${conversationId}`

In-memory fallback: Use `Map<string, SaveMeta>` keyed by `${userId}:${conversationId}`. Check `isRedisAvailable()` at the top of each function (same pattern as conversationStore.ts). The in-memory fallback is best-effort — limited to current process lifetime.

Exported functions:
1. `upsertSave(userId, conversationId, meta)` — HSET the save hash fields (name, characterClass, pronouns, turnCount, savedAt, lastPlayedAt, mode as strings). Set TTL on hash with EXPIRE. ZADD to sorted set index with score = lastPlayedAt. Trim: if ZCARD > MAX_SAVES, ZRANGE to get oldest, DEL their hashes, ZREMRANGEBYRANK to trim the set.
2. `listSaves(userId)` — ZRANGE with REV:true (0 to -1) to get conversationIds newest-first. For each, HGETALL the hash. Filter out any with empty/missing name (orphaned index entries). Return SaveRecord[].
3. `deleteSave(userId, conversationId)` — DEL the hash key, ZREM from sorted set. Do NOT delete the conversation itself.
4. `renameSave(userId, conversationId, newName)` — HSET just the name field on the existing hash. Throw if hash doesn't exist (return false or throw — route will 404).
5. `findByConversationId(userId, conversationId)` — HGETALL the hash key. Return SaveMeta | null. Used by chat.ts auto-update hook.

For all Redis operations, wrap in try/catch and fall back to in-memory on Redis errors (matching conversationStore.ts pattern). Log errors with `logEvent` from logger.js.

**saves.ts** — Create REST routes following the pattern in chat.ts:

Import Router from express, z from zod, saveStore functions, logEvent, AuthenticatedRequest type, ConversationOwnershipError.

Zod schemas:
```typescript
const saveBodySchema = z.object({
  conversationId: z.string().uuid(),
  name: z.string().min(1).max(50).trim(),
  characterClass: z.string().optional().default(''),
  pronouns: z.string().optional().default(''),
  mode: z.enum(['single', 'multi']).optional().default('single'),
});

const renameBodySchema = z.object({
  name: z.string().min(1).max(50).trim(),
});
```

Endpoints:
1. `GET /api/saves` — Call listSaves(req.userId!). Return 200 with `{ saves: SaveRecord[] }`.
2. `POST /api/saves` — Validate body with saveBodySchema. Verify the conversationId belongs to req.userId by calling `getOrCreate(conversationId, userId)` from conversationStore (this does the IDOR check). Call upsertSave with meta. Return 201 with `{ save: SaveRecord }`.
3. `PUT /api/saves/:id/name` — `:id` is conversationId. Validate body with renameBodySchema. Verify ownership via findByConversationId. If no save found, 404. Call renameSave. Return 200 with `{ ok: true }`.
4. `DELETE /api/saves/:id` — `:id` is conversationId. Call deleteSave. Return 200 with `{ ok: true }`. (Idempotent — no error if already deleted.)

All endpoints use `req.userId!` (requireAuth is applied at app.ts level). All errors follow existing pattern: `res.status(N).json({ error: "message" })`.

// Auto-update existing save metadata (lastPlayedAt, turnCount) on DM response
if (fullText && req.userId) {
  try {
    const existingSave = await findByConversationId(req.userId, conversation.id);
    if (existingSave) {
      await upsertSave(req.userId, conversation.id, {

        turnCount: Math.floor(conversation.history.length / 2),

    }, err);

}
