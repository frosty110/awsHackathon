  <name>Task 1: Replace useSSEChat mock with real SSE streaming fetch</name>
  <files>client/src/hooks/useSSEChat.ts</files>
  <action>
Rewrite the internals of useSSEChat.ts while keeping the EXACT same external interface: `{ messages, isLoading, sendMessage, reset }`.

Remove: MOCK_RESPONSES array, pendingTimeout ref, the setTimeout mock block.

Add:
- `const conversationIdRef = useRef<string | null>(null)` -- stores server-provided conversationId
- `const pendingAbort = useRef<AbortController | null>(null)` -- allows aborting in-flight stream on reset

**sendMessage signature change:** The function must now accept an optional second parameter for dice result: `sendMessage(content: string, diceResult?: number)`. This is additive -- callers that pass only content still work. The hook return type stays `{ messages, isLoading, sendMessage, reset }`.

**sendMessage implementation (replace the mock block):**
1. Determine role: if `content.startsWith('\u{1F3B2}')` then `'dice'`, else `'player'`
2. Create user message and add to messages state, set isLoading true
3. Create AbortController, store in `pendingAbort.current`
4. `fetch('/api/chat', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ conversationId: conversationIdRef.current, message: content, ...(diceResult != null ? { diceResult } : {}) }), signal: abortController.signal })`
5. If `!response.ok || !response.body`, throw error
6. Get `reader = response.body.getReader()`, create `TextDecoder`
7. Add empty streaming DM message placeholder: `{ id: crypto.randomUUID(), role: 'dm', content: '', isStreaming: true }`
8. Read loop: `while (true)` with `reader.read()`, break on `done`
9. Decode chunk, append to `pending` buffer, split on `\n\n`
10. For each complete event: skip if not starting with `data:`, extract payload after `data: `, skip `[DONE]`
11. Parse JSON: if `parsed.conversationId` -> store in `conversationIdRef.current`. If `parsed.error` -> throw. If `parsed.text` -> update the DM message content by appending delta (use `setMessages` with map to find the dmMessageId and append to its content)
12. After loop: mark streaming message as `isStreaming: false`
13. Catch: if not AbortError, add error DM message: "The connection to the Dungeon Master was lost. Please try again."
14. Finally: clear `pendingAbort.current`, set `isLoading(false)`

Make sendMessage `async` inside useCallback. The useCallback wrapper stays the same.

**reset implementation:**
- If `pendingAbort.current` exists, call `.abort()` and set to null
- Set `conversationIdRef.current = null` (fresh conversation on next send)
- Clear messages, set isLoading false

**Cleanup effect:** Remove the old pendingTimeout cleanup. Add cleanup that aborts pending request on unmount:
```
useEffect(() => {
  return () => { pendingAbort.current?.abort(); };
}, []);
```

IMPORTANT: Use `import type { Message }` (not `import { Message }`) per verbatimModuleSyntax tsconfig setting.
