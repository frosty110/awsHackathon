For each service file, add `import tracer from 'dd-trace';` at the top.

**bedrock.ts** — `bedrock.dm_response` span:
- Wrap the main streaming function (likely `streamBedrockResponse` or similar) with:
  ```typescript
  tracer.llmobs.trace(
    { kind: 'llm', name: 'bedrock.dm_response', modelName: BEDROCK_MODEL_ID, modelProvider: 'aws' },
    async (span) => {
      // ... existing streaming logic ...
      // After stream completes, BEFORE return:
      tracer.llmobs.annotate(span, {
        inputData: messages.map(m => ({ role: m.role, content: String(m.content) })),
        outputData: { role: 'assistant', content: fullText },
        metrics: { inputTokens, outputTokens, totalTokens: inputTokens + outputTokens },
      });
      return fullText;
    }
  );
  ```
- Use `kind: 'llm'` and include `modelName` and `modelProvider` in the span options.
- Extract token counts from `chunk.metadata.usage` in the ConverseStream response (inputTokens, outputTokens).
- Note: This may create duplicate spans with auto-instrumentation. That is acceptable for the demo — see research Pitfall 6.

**neo4j.ts** — `neo4j.lore_query` span:
- Wrap the main query function (likely `queryLore` or similar) with:
  ```typescript
  tracer.llmobs.trace(
    { kind: 'tool', name: 'neo4j.lore_query' },
    async (span) => {
      // ... existing query logic ...
      tracer.llmobs.annotate(span, {
        inputData: JSON.stringify({ entities }),
        outputData: JSON.stringify({ recordCount: records.length }),
      });
      return records;
    }
  );
  ```
- Use `kind: 'tool'` (not 'llm' — this is a non-LLM external call).

**tts.ts** — `minimax.tts` span:
- Wrap the main TTS function (likely `generateSpeech` or similar) with:
  ```typescript
  tracer.llmobs.trace(
    { kind: 'tool', name: 'minimax.tts' },
    async (span) => {
      // ... existing TTS logic ...
      tracer.llmobs.annotate(span, {
        inputData: text.slice(0, 200),
        outputData: JSON.stringify({ byteLength: buffer.byteLength }),
      });
      return buffer;
    }
  );
  ```
- Use `kind: 'tool'` (not 'llm').

CRITICAL RULES (from research):
- Use `tracer.llmobs.trace()` NOT `tracer.startSpan()`. The roadmap outline said startSpan — that is WRONG. Only llmobs.trace() produces spans visible in LLM Observability UI.
- Call `tracer.llmobs.annotate(span, ...)` BEFORE the async callback returns. The span finishes on callback return. Late annotate() silently drops data.
- If a service file does not exist yet, create a minimal stub with the span wrapper and a TODO comment for the implementing phase. Export the function so the implementing phase can fill in the real logic inside the wrapper.
