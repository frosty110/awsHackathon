  <action>
1. Install `@datadog/datadog-api-client` as a devDependency in the server workspace:
   ```bash
   npm install --save-dev @datadog/datadog-api-client -w server
   ```

2. Create `scripts/create-dashboard.ts` at the project root (NOT inside server/). The script:
   - Imports from `@datadog/datadog-api-client` (both the top-level client module and v1 namespace).
   - Calls `client.createConfiguration()` which reads `DD_API_KEY` and `DD_APP_KEY` from environment automatically.
   - Creates a dashboard with `v1.DashboardsApi.createDashboard()`.

   Dashboard definition:
   - Title: `[Hackathon] AI Dungeon Master - LLM Observability`
   - Layout type: `ordered`
   - Template variables: `env` (default: `development`), `service` (default: `server`)

   Three widgets:

   **Widget 1 — Token Usage (timeseries, bars):**
   ```
   title: 'Bedrock Token Usage'
   type: 'timeseries'
   query: 'sum:trace.aws.bedrockruntime.converse_stream{service:$service,env:$env}.as_count()'
   displayType: 'bars'
   ```
   Note: The exact metric name may need adjustment after the smoke test (see research Open Question 1). Use this as the initial value — the executor should update it if the smoke test reveals a different metric name.

   **Widget 2 — Request Latency p95 (timeseries, line):**
   ```
   title: 'Chat Request Latency p95'
   type: 'timeseries'
   query: 'p95:trace.express.request{service:$service,env:$env,resource_name:POST_/chat}'
   displayType: 'line'
   ```

   **Widget 3 — Live Traces (list_stream):**
   ```
   title: 'Live Traces'
   type: 'list_stream'
   dataSource: 'trace_stream'
   queryString: 'service:$service env:$env'
   columns: [resource_name (auto), @duration (auto), status (auto)]
   responseFormat: 'event_list'
   ```

   At the end, log the dashboard URL:
   ```typescript
   console.log('Dashboard created:', result.url);
   ```

   Add error handling: wrap in try/catch, on error log the error message and exit with code 1. Include a helpful message if 403 is detected: "403 Forbidden — ensure DD_APP_KEY is set (Application Key, not API Key)."

3. Add a run script to root `package.json`:
   ```json
   "create-dashboard": "npx tsx scripts/create-dashboard.ts"
   ```
   This goes in the ROOT package.json scripts, not server/package.json, because the script is a project-level tool.

IMPORTANT constraints from research:
- The script must run AFTER real trace data exists in Datadog. The `trace_stream` widget needs at least one span to resolve the service. Do NOT run this during the build — it is a pre-demo step. Add a comment at the top of the script noting this constraint.
- DD_APP_KEY is a Datadog Application Key (NOT the same as DD_API_KEY). It must be created in Datadog Organization Settings > Application Keys.
- Use the `@datadog/datadog-api-client` library (NOT raw fetch). The library handles auth headers, retries, and rate limiting.
