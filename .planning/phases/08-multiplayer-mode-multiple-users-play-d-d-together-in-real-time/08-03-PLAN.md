    1. Create `server/src/sockets/roomHandlers.ts`:
       - Export `registerRoomHandlers(io, socket)` function (typed with Socket.IO generics from types.ts)
       - **room:create** handler:
         - Extract `{ displayName, characterClass }` from event data
         - Generate unique room code via `generateUniqueRoomCode()`
         - Create conversation via `getOrCreate()` (from conversationStore) to get a conversationId for the room
         - Call `createRoom(code, conversationId)` from roomStore
         - Create Player object: `{ socketId: socket.id, displayName, characterClass, connected: true, ready: false, submittedAction: null }`
         - Call `addPlayer(code, player)`
         - Store room code in `socket.data.roomCode = code`, `socket.data.displayName = displayName`, `socket.data.characterClass = characterClass`
         - `socket.join(code)` — join the Socket.IO room
         - Emit `room:created` to the creating socket with `{ code }`
         - Emit `room:state` to the creating socket with full room state payload
       - **room:join** handler:
         - Extract `{ code, displayName, characterClass }`
         - Normalize code to uppercase
         - Get room — if not found, emit `room:error` with "Room not found" and return
         - If room has 4 players already, emit `room:error` with "Room is full" and return
         - Create Player, call `addPlayer`
         - Store in socket.data, `socket.join(code)`
         - Emit `room:player-joined` to room (all players) with PlayerPayload
         - Emit `room:state` to the joining socket with full room state
         - If room phase is not "lobby" (mid-game join per locked decision):
           - Also send the room's currentDmText if non-empty so late joiner sees the last DM response
       - **room:ready** handler:
         - Get roomCode from socket.data
         - Call `markPlayerReady(roomCode, socket.id)`
         - Broadcast updated `room:state` to room
         - Check game start condition: `getConnectedPlayerCount(roomCode) >= 2 && getAllReadyCount(roomCode) === getConnectedPlayerCount(roomCode)`
         - If true:
           - Set room phase to "playing"
           - Emit `room:started` to room
           - Trigger DM opening monologue: use `triggerDMOpening(io, roomCode)` from turnHandlers (imported). This sends a DM opening narrative before the first timer.
       - **disconnect** handler:
         - Get roomCode from socket.data, bail if none
         - Call `markPlayerDisconnected(roomCode, socket.id)`
         - Emit `room:player-disconnected` to room with `{ socketId, displayName }`
         - If room is in `collecting-actions` phase and this player hadn't submitted, auto-fill: `submitAction(roomCode, socket.id, "${displayName} hesitates, unsure of what to do.")`. Then check `allActionsSubmitted` and trigger DM if all submitted.
         - Check if ALL players are now disconnected: if `getConnectedPlayerCount(roomCode) === 0`, call `deleteRoom(roomCode)` to prevent memory leak.
       - Handle reconnection: in `io.on("connection")` callback (in sockets/index.ts, registered there), if `socket.recovered` is true, get roomCode from socket.data, call `markPlayerReconnected`, emit `room:player-reconnected`, and send `room:state` to the reconnected socket.

    2. Create `server/src/sockets/chatHandlers.ts`:
       - Export `registerChatHandlers(io, socket)` function
       - **chat:send** handler:
         - Extract `{ text }` from event data
         - Create ChatMessagePayload: `{ id: crypto.randomUUID(), fromSocketId: socket.id, fromName: socket.data.displayName, fromClass: socket.data.characterClass, text, timestamp: Date.now() }`
         - Emit `chat:message` to room via `socket.to(socket.data.roomCode).emit(...)` (excludes sender — sender already has their own message)
         - IMPORTANT: Do NOT store these messages in conversationStore or include in any Bedrock prompts. Player chat is invisible to the DM per locked decision.
       - **chat:react** handler:
         - Extract `{ messageId, emoji }`
         - Validate emoji is in allowed set: ["thumbs_up", "skull", "fire", "swords", "sparkles", "laugh"] (Claude's Discretion: 6 common D&D-themed reactions)
         - Emit `chat:reaction` to room via `io.to(socket.data.roomCode).emit(...)` with `{ messageId, emoji, fromSocketId: socket.id, fromName: socket.data.displayName }`
       - **dice:roll** handler:
         - Extract `{ result }`
         - Emit `dice:rolled` to room via `io.to(socket.data.roomCode).emit(...)` with `{ socketId: socket.id, displayName: socket.data.displayName, result }`
         - All dice rolls visible to all players per locked decision.

  <action>
    1. Create `server/src/sockets/turnHandlers.ts`:
       - Import `io` from `../sockets/index.ts`, room store functions, conversation store functions, `streamBedrockResponse` and `buildMultiplayerSystemPrompt` from bedrock
       - Export `registerTurnHandlers(io, socket)` function:
         - **turn:submit-action** handler:
           - Extract `{ action }` from event data
           - Get roomCode from socket.data
           - Get room — if not in `collecting-actions` phase, ignore (emit nothing, return)
           - Call `submitAction(roomCode, socket.id, action)`
           - Emit `turn:player-submitted` to room with `{ socketId: socket.id }` (action text hidden per Claude's Discretion)
           - If `allActionsSubmitted(roomCode)`:
             - Get room, `clearTimeout(room.timerHandle)`, set `room.timerHandle = null`
             - Call `triggerDMResponse(io, roomCode)`
       - Export `startTurnTimer(io, roomCode, durationMs = 60_000)`:
         - Get room, set `room.phase = "collecting-actions"`, `room.timerStartedAt = Date.now()`
         - Reset all actions via `resetActions(roomCode)`
         - Emit `turn:timer-start` to room with `{ durationMs, endsAt: room.timerStartedAt + durationMs }`
         - Set `room.timerHandle = setTimeout(() => { ... }, durationMs)`:
           - In timeout callback: auto-fill missing actions for connected players: `"${player.displayName} follows the group cautiously."` (Claude's Discretion: passive, non-disruptive default)
           - Then call `triggerDMResponse(io, roomCode)`
       - Export `triggerDMOpening(io, roomCode)`:
         - Get room. Set phase to `dm-responding`.
         - Build multiplayer system prompt via `buildMultiplayerSystemPrompt([...room.players.values()])`
         - Get or create conversation: `getOrCreate(room.conversationId)`
         - Build opening message as user turn: `"The party has gathered. Begin the adventure at the Shattered Crown Tavern. Introduce the scene and each character by name and class."`
         - Append this user message to conversation store
         - Emit `dm:stream-start` to room
         - Call `streamBedrockResponse(getWindowedHistory(room.conversationId), onChunk, { multiplayerPrompt: buildMultiplayerSystemPrompt([...room.players.values()]) })` where onChunk does:
           - `room.currentDmText += text`
           - `io.to(roomCode).emit("dm:chunk", { text })`
         - On success: append assistant message to conversation store, emit `dm:stream-end` with full text, reset `room.currentDmText = ""`
         - Set `room.phase = "playing"`
         - After 3-second pause (Claude's Discretion), start first turn timer: `setTimeout(() => startTurnTimer(io, roomCode), 3_000)`
         - On error: emit `dm:error` with `"The Dungeon Master was lost to the void."`, set phase back to "playing", start timer anyway
       - Internal `triggerDMResponse(io, roomCode)`:
         - Get room, set `phase = "dm-responding"`
         - Build combined action message from all players:
           ```
           The players act simultaneously:
           [PlayerName the ClassName]: action text
           [PlayerName2 the ClassName2]: action text
           ...

           Weave all of these into one dramatic narrative. You have full creative authority — actions may succeed, fail, or cancel each other out.
           ```
         - Append combined user message to conversation store
         - Emit `dm:stream-start`
         - Stream via `streamBedrockResponse(getWindowedHistory(room.conversationId), onChunk, { multiplayerPrompt: buildMultiplayerSystemPrompt([...room.players.values()]) })`
         - onChunk: accumulate in `room.currentDmText`, emit `dm:chunk` to room
         - On success: append assistant message, emit `dm:stream-end`, reset `room.currentDmText`, `resetActions(roomCode)`, set phase to "playing"
         - 3-second pause then `startTurnTimer(io, roomCode)` (Claude's Discretion: 3s pause after DM narration)
         - On error: emit `dm:error`, reset actions, set phase to "playing", start timer anyway to keep game moving

    2. Add `buildMultiplayerSystemPrompt` to `server/src/services/bedrock.ts`:
       - Add export function `buildMultiplayerSystemPrompt(players: Array<{ displayName: string; characterClass: string }>): string`:
         - Build roster: `players.map(p => "- ${p.displayName}: ${p.characterClass}").join("\n")`
         - Return: `${DM_SYSTEM_PROMPT}\n\n## Multiplayer Party\nThis is a multiplayer session. The party consists of:\n${roster}\n\nWhen players act simultaneously, weave ALL actions into ONE cohesive narrative. You have full authorial control — actions may succeed, fail, contradict, or complement each other. Do NOT narrate each player's action separately. Create a unified, dramatic story beat. Address characters by their display names.`
       - Update `streamBedrockResponse` to accept optional `multiplayerPrompt` in options:
         - Add `multiplayerPrompt?: string` to options type
         - If `options?.multiplayerPrompt` is provided, use it as the system prompt instead of the default single-player prompt (it already includes DM_SYSTEM_PROMPT as its base)
         - The existing `characterClass` option is for single-player only — multiplayer uses `multiplayerPrompt` which already contains all player classes
