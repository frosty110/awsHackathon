<objective>
Add Bedrock concurrency cap via p-queue and extract prompt construction logic into a dedicated promptBuilder.ts service.

Purpose: Without concurrency control, 1000 concurrent users can fire unlimited simultaneous Bedrock calls, causing ThrottlingException cascades. The DM_SYSTEM_PROMPT (160 lines) living in bedrock.ts mixes content concerns with transport concerns, making prompt iteration harder. This plan fixes both.
Output: p-queue wrapping all Bedrock calls with concurrency 20; `promptBuilder.ts` owning all prompt content; `bedrock.ts` as pure AWS transport.
</objective>
