<objective>
Add Redis error resilience to all 5 public methods in conversationStore so that mid-run Redis failures degrade gracefully to in-memory instead of propagating as 500 errors.

Purpose: When Redis drops mid-request (connection timeout, eviction, network blip), the conversationStore currently throws unhandled promise rejections that surface as 500 errors to users. At 1000 concurrent users, Redis transient failures are expected. The fix wraps each Redis branch in try/catch with console.error logging and fall-through to the existing in-memory path.

Output: conversationStore.ts with try/catch in all 5 public methods' Redis branches.
</objective>
