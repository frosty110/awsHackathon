**C-1: Auth enforcement in `server/src/app.ts`**

Import `requireAuth` from `./middleware/auth.js` (it already exists but is only partially imported — `optionalAuth` is imported on line 12; add `requireAuth` to that import).

In the Section 7 comment block (lines 44-49), insert `requireAuth` as the first middleware argument before each rate limiter. The pattern:

```
app.use("/api/chat", requireAuth, chatRateLimiter);
app.use("/api/narrate", requireAuth, narrateRateLimiter);
app.use("/narrate", requireAuth, narrateRateLimiter);
app.use("/api/music", requireAuth, musicLimiter);
app.use("/music", requireAuth, musicLimiter);
app.use("/api/scene-video", requireAuth);
```

CRITICAL: Do NOT add requireAuth to `/api/auth/register`, `/api/auth/login`, `/health`, `/api/health`, or `/api/usage`. These must remain open.

Note: The `/narrate` path must also get `requireAuth` because the narrate router registers both `/narrate` and `/api/narrate` paths. Without this, POST to `/narrate` bypasses auth. Also add `requireAuth` to `/music` for the same reason (music route also has dual paths).

This overrides the Phase 09-03 decision "optionalAuth globally (not requireAuth)" — the code review (C-1) post-dates that decision and explicitly requires auth enforcement on game routes.

**H-1: JWT algorithm pinning in `server/src/middleware/auth.ts`**

In `requireAuth` function (line 49): Change `jwt.verify(token, getJwtSecret())` to `jwt.verify(token, getJwtSecret(), { algorithms: ["HS256"] })`.

In `optionalAuth` function (line 78): Same change — add `{ algorithms: ["HS256"] }` as the third argument to `jwt.verify`.

IMPORTANT: The verify option is `algorithms` (plural, array of strings), NOT `algorithm` (singular). This is the jsonwebtoken API convention.

In the Socket.IO auth middleware in `server/src/sockets/index.ts` at line 102: Also add `{ algorithms: ["HS256"] }` to the `jwt.verify` call there.

**H-1 continued: JWT sign algorithm pinning in `server/src/routes/auth.ts`**

In the login route (line 126-130): Change the `jwt.sign` options from `{ expiresIn: "7d" }` to `{ algorithm: "HS256", expiresIn: "7d" }`.

IMPORTANT: The sign option is `algorithm` (singular string), NOT `algorithms`. Sign and verify use different option names.

**M-3: Password policy in `server/src/routes/auth.ts`**

In the register route (line 35): Change `password.length < 6` to `password.length < 8 || password.length > 128`. Update the error message to `"Password must be 8-128 characters"`.

**H-2: Fix `skipMiddlewares: true` to `skipMiddlewares: false`**

In `server/src/sockets/index.ts` at line 77, in the `connectionStateRecovery` config object: Change `skipMiddlewares: true` to `skipMiddlewares: false`.

This ensures that when a socket reconnects within the 2-minute recovery window, the JWT authentication middleware still runs. Without this fix, a user whose token expired or was revoked during the disconnect window can reconnect without re-authenticating.
