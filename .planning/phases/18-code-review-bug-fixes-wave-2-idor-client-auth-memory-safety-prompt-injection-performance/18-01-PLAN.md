<task type="auto">
  <name>Task 1: IDOR fix — conversation ownership binding</name>
  <files>server/src/services/conversationStore.ts, server/src/routes/chat.ts, server/src/routes/narrate.ts</files>
  <action>
    1. In `conversationStore.ts`:
       - Add `userId?: string` to the `Conversation` type.
       - Update `IConversationStore.getOrCreate` signature to accept `userId?: string` as the second parameter (shift characterClass/pronouns to 3rd/4th).
       - In `InMemoryConversationStore.getOrCreate`:
         - When creating a new conversation (Redis or in-memory), set `userId` on the object.
         - When retrieving an existing conversation:
           - If `convo.userId` is set AND `userId` is provided AND they differ, throw a new `ConversationOwnershipError` (create this as an exported class extending Error).
           - If `convo.userId` is undefined but `userId` is provided, claim ownership: `convo.userId = userId` (migration path for legacy conversations).
       - Update the bound `getOrCreate` export to match the new signature.

    2. In `chat.ts`:
       - Import `AuthenticatedRequest` from `../middleware/auth.js`.
       - Cast `req` as `AuthenticatedRequest` at the top of the handler.
       - Pass `req.userId` as the second argument to `getOrCreate(body.conversationId, req.userId, characterClass, pronouns)`.
       - Import `ConversationOwnershipError` from conversationStore.
       - Wrap the `getOrCreate` call in try/catch: if `ConversationOwnershipError`, return `res.status(403).json({ error: "Access denied" })`.

    3. In `narrate.ts`:
       - Same pattern: import AuthenticatedRequest, cast req, pass `req.userId` to `getOrCreate`.
       - Handle `ConversationOwnershipError` with 403.
       - Note: The narrate route creates new conversations (no conversationId from body typically), so ownership is set on creation.

    IMPORTANT: Handle the migration case — conversations created before this change have no `userId`. The check must only enforce ownership when `convo.userId` is already set. This prevents false 403s for existing sessions.
  </action>
  <verify>
    - `npx tsc --noEmit` compiles clean.
    - `npm test` (from server/) passes — existing conversationStore tests may need updating if they call getOrCreate with the old signature; add userId parameter to test calls.
  </verify>
  <done>
    - New conversations have userId set from req.userId.
    - Attempting to access another user's conversation returns 403.
    - Legacy conversations (no userId) are claimed by the first authenticated user who accesses them.
  </done>
